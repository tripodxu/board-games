# 接力协议（handoff）

> 场景：任务跨多轮/多会话/多 agent（实现→审查→修复→部署），或当前 agent 上下文将满。
> 目标：**下一个 agent 用 5 分钟恢复全部上下文，不需要重读代码库。**

## 1. 交接物

| 文件 | 位置 | 入库？ | 内容 |
|---|---|---|---|
| 进行中交接 | `.work/handoff.md` | ❌ gitignore | 当前状态、未解决问题、下一步 |
| 审查报告 | `.work/review.md` | ❌ gitignore | 审查结论 |
| 任务板 | `.work/tasks.md` | ❌ gitignore | 并行任务认领状态 |
| 长期记忆 | `docs/memory/MEMORY.md` | ✅ | 完成后把结论**置顶**沉淀 |
| 状态更新 | `docs/status.md` | ✅ | 行为变更/新限制 |

> `.work/` 已写入 `.gitignore`（可含本机绝对路径与临时结论）。
> **接力结束（任务完成或放弃）时，必须把结论沉淀进 MEMORY.md 与 status.md，否则下一个
> 全新 clone 的 agent 永远看不到。**

## 2. handoff 模板（.work/handoff.md）

```markdown
# handoff · <任务名>
- 角色：<engine-dev / jev-dev / ui-dev / reviewer>
- 日期：2026-09-28
- 状态：<进行中 · 待审查 · 待修复 · 已完成>
- 相关 commit：<sha 或 "未提交，改动在下列文件">

## 任务背景（3 行以内）
<为什么做这件事，验收标准是什么>

## 当前状态
- 已做：<具体到文件与函数>
- 已验证：<跑过什么命令，结果如何；未跑就说"未验证">
- 已知好/坏：<有没有引入临时方案、console.log、被跳过的用例>

## 未解决（按优先级）
1. <问题 + 已排除的假设 + 需要什么信息才能继续>

## 下一步（具体到可执行）
1. <打开哪个文件、改哪个函数、期望行为>
2. <跑什么命令验收>

## 上下文备忘
<容易再次踩的坑、与其它任务的耦合点、编排者的特别交代>
```

## 3. 恢复步骤（接力的 agent 按序做）

1. 读 `.work/handoff.md` 全文（没有就问编排者要，或从 memory 最新条目重建）。
2. 读 `docs/memory/MEMORY.md` **最新 3 条**（项目级近期决策与坑）。
3. 按 handoff「下一步」只打开指名的文件；需要背景时按
   [reading-paths.md](reading-paths.md) 补读对应文档，**不要通读源码**。
4. 开干前先复现/确认 handoff 里「已验证」的状态（重跑验收命令）。
5. 完成后：更新 status.md → memory 置顶一条 → 把 handoff 状态改为「已完成」
   （或直接删除，结论已沉淀）。

## 4. 纪律

- handoff 写**事实**，不写客套；「未验证」必须显式写出，不许暗示完成。
- 一个任务同时只允许一个活跃 handoff；并行子任务的进展写 `.work/tasks.md`。
- 禁止把 handoff 当聊天记录；超过 30 行说明拆分粒度有问题，回到编排者重新拆任务。
