# 官方 API 基准数据集（渠道判别参照系）

> 已完成的渠道检验：[free 腿（zen-o2a）≡ 官方，统计上不可区分](free-vs-official-2026-10-14.md)（2026-10-14）。

> 生成于 2026-10-14。用途：给「某个新渠道/网关/部署是不是真 Jev」提供**可复现的参照系**。
> 计划与判据见 [../plans/2026-10-14-official-baseline.md](../plans/2026-10-14-official-baseline.md)。

## 这是什么

把**真实对局里的局面**（非合成）重建为发给 Jev 的输入，用 **TypeSafe 官方 API**（`api.typesafe.ai`，
模型 `jev-1.13.0`，单上游、无多腿路由）每个局面重复问若干次，记录每次的选点与完整概率分布。

这组数据 = **「真 Jev」对这些局面的回答分布**。之后任何渠道在同一批局面上跑同样流程，
比对选点一致率与概率向量距离，即可判断它是否等价于真 Jev。

## 文件

| 文件 | 内容 |
| --- | --- |
| `official-baseline-large-500x6.jsonl` | **500 局面 × 6 次**。判定渠道等价的主集（95% CI 半宽 ±4.4pt） |
| `official-baseline-small-96x10.jsonl` | **96 局面 × 10 次**。重复次数多，刻画 Jev 自身决策分布；作小样本留存 |
| `official-baseline-instructions.json` | instructions 全文**按 SHA 去重**（全数据集仅 4 份唯一，16KB）。每行只存 SHA，靠它复现完整请求 |

> **为什么两批都留**：单靠哪一批都不够——96 局面判不了渠道等价（CI 太宽），6 次重复撑不起分布估计。
> 横向比渠道用大样本，刻画「Jev 有多确定」用小样本。两批整体众数占比 93.2% vs 90.9%（差 2.3pt），互相印证。

## 每行（一条 JSONL 记录）的字段

```
id, label, batch, game, ply, side     局面来源：档标签 / 批次 / 棋谱文件 / 第几手 / 该手执子方
played                                  生产当时实走的着法
state                                   完整发给 Jev 的 state（board_ascii、双方子力坐标、
                                        rules、候选、tactics 事实）—— 可原样重建
criteria                                逐候选的引擎标签（you:*/deny:*/block:five）
instructionsSha                         指向字典里的那份 instructions
calls[]                                 每次调用：{choice, conf, model, probs}（probs 是完整概率分布）
mean                                    6/10 次概率向量的平均 —— 判等价时算 TV 距离用
replies                                 有效（非错误）回复数
```

## 复现性与两个关键事实

**1. instructions 由「局面的 tactics 事实」决定，不由档位决定。**
实测同一 SHA 横跨 v14/v14-plus/v15/v14.1 等多档（`bc11051b…` 覆盖 168 个局面）。
之前「instructions 由注册档位+代码确定」的说法**不准确**——差异来自局面里实际追加了哪些事实语句。
所以本数据集**自带 instructions 字典**，复现不依赖任何代码版本。已全量校验：
**500/500 局面可从存档 state 重建出逐字相同的 instructions（SHA 全部命中，0 不符）。**

**2. 存档 state 不含内部 `board` 数组**，需从 `black_stones`/`white_stones` 的坐标重建
（坐标约定：**字母=列、数字=行**，见 `gomoku.ts` 的 `notation(r,c)=colName(c)+(r+1)`；
搞反会导致候选集全错——本项目踩过这个坑）。

## 怎么用：判别一个新渠道

1. 固定这套局面：读 `*-large-500x6.jsonl` 的 `state` + `criteria`，从字典取 `instructions`，
   组装成与官方完全相同的请求。
2. 用**待判渠道**打每个局面 **≥6 次**（与参照同量），记录选点。
3. 算两个量并与基准比：
   - **众数一致率**：待判渠道每局的众数 == 官方参照众数 的比例（跨 500 局）
   - **概率向量 TV 距离**：`0.5·Σ|p_待判 − p_官方|`，取均值
4. **判读**（参照基准自身众数占比 93.2%、R=15.3）：
   - 众数一致 **>85%** 且 TV **<0.1** ⇒ 与真 Jev 行为等价
   - 一致 **60–85%** 或 TV **0.1–0.3** ⇒ 部分偏离，报出偏差量
   - 一致 **<60%** 或 TV **>0.3** ⇒ 不是同一个模型/部署
   > 注意噪声地板：官方**自身**重复问也只有约 93% 众数一致，所以「100% 一致」不可能也不必要。

## 已知的局限（务必读）

- **重建输入 ≠ 生产实送。** 实测「生产当时实走的着法 ∈ 官方 10 次采样 = 100%，但 = 众数仅 31.3%」
  ⇒ 说明我们重建的 state 与生产当时真正送进网关的有系统性差异（`experience` 字段、候选截取顺序等）。
  **本数据集作为「同一输入下渠道间的横向对比」有效；不能用来复现生产的具体对局。**
- **Jev 是随机的，不是确定函数。** 官方自身众数占比 90.9–93.2%（约 7–9% 的局面重复问会给出不同着法），
  R=众数/Σp²≈15 ≫1 表明它比自报概率确定得多（**不按报出的概率抽样**）。任何单次调用对比都要按此噪声折价。
- 模型名用 `jev-1.13.0` 或 `jev-latest`；`typesafe/jev`、`jev-1.13` 会被网关/官方判为 Unknown model。
- 官方 API 从 box（出口 IP 185.242.234.48）可用、实测无限速；**从某些地域直连返回 451**（Typesafe is not available in your region）。
