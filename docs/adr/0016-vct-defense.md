# ADR-0016：战术层新增「连续威胁防守」（`vctDefense`：对手的混合链也要拆）

- 状态：accepted（2026-10-02）
- 背景：v11 `v11-vct` 上线后连打了两轮 `rapfi@500ms` 对照（tag `exp-20261002055817`、
  `exp-20261002094817`），逐手离线复算（`.work/v12-defence-probe.mjs`）得到三条硬数据：
  1. 单变量对手下，v11 的**进攻侧已经没有可见的漏杀**（三轮实验一致）：我方回合里「有必胜链」
     的占比 41%，走了链首步的比例 84/87、69/72、72/72，「机会真丢」0 手。**输的局全是
     「我方算不出强制胜」**的局面 —— 两轮的三局负局（v11 的 28 / 17 个回合）**一次都没报出链**。
  2. 真正的漏洞在**防守侧**：计时轮 175 个 v11 回合里，**20 手（11%）「我方无杀而对手有连续
     威胁链」**；其中**实走之后对手仍有链的 8 手（40%）全部落在三局负局**里
     （`#5 6db0253d` ply17/19/21/23、`#6 68f62f4b` ply32/34、`#8 f463acff` ply24/26），
     而 8 手里有 **4 手的实走正是对手的链首点** —— 占掉链首并没有拆掉整条链。
     直接走链首能拆的比例是 **12/20（60%）**，且这 12 手全部由**已有的** `vcfDefense`（10）与
     `block`（2）拆掉了 ⇒ 现有防守层**要么已经拆掉，要么根本没看见**：它只验纯冲四链
     （`vcfWin`），对手把链换成「活三逼迫 + 冲四收尾」，`vcfDefense` 就放行。
  3. 局面是**从什么时候输的**（`.work/v12-turning-point.mjs`，独立实现 fivePoints/fourMoves/
     live3Moves）：三局负局的「点无回头路」分别在 **ply17 / ply34 / ply26**，而**最后一口气**
     （盘面上还有候选能拆）分别在 **ply15（40 个候选里 2 个能拆）/ ply32（2/40）/ ply24（1/40）**，
     实走分别是 `B12/vcfDefense`、`G7/live3Attack`、`I11/parry` —— **一次都没走那 1–2 个能拆的点**。
     对照局 `#1`（胜）ply17 的对手链被 `D12/block` 拆掉后，ply19/21 我方 `open4 → win`。
     压力轨迹还显示：对手「造四点」的个数在杀棋前 **4–6 手**就开始爬升（`#5` ply11 起 0→3、
     `#8` ply22 起 2→3→6、`#6` ply24 起 3→4→3→5），而我方那几手往往还在跑 `live3Attack`。
- 候选集怎么选（`.work/v12-defuse-strategies.mjs`，在「我方无杀而对手有链」的回合上对比四种
  候选生成策略的命中率）：只试对手链首 **12/20**；链首 + 链上各点 **12/20**；
  **再加「链点的车氏 ≤2 邻域」13/20**（平均试 7.8 点，19ms / 最坏 103ms）；
  全部邻近空点按到链距离排序 **13/20**（15.2 点，25ms / 218ms）。
  第二轮（`exp-20261002055817`，28 个机会）同序为 19 / 21 / 21 / 22；直连轮
  （`exp-20261002080446`，153 个机会，两侧都是 proxy，半个样本是 v10 的回合）101 / 107 / 111 / 113。
  ⇒ **只有「链点邻域」这一档能多抓到东西**，而且两轮各只多抓一手：
  计时轮 `#8` ply24 → `K9`（实走 `I11/parry`）、首轮 `#6` ply52 → `K8`（实走 `G10/parry`）。
  两轮合计 48 个「我方无杀而对手有链」的回合：实走拆掉 33、漏 15，**漏的 15 个里只有 2 个
  存在能拆的点却没走**，其余 13 个**全盘候选都拆不掉**（点无回头路）。

## 决定

1. **引擎新增可选方法 `vctDefense(st, defenderId, maxPlies?, opts?)`**（返回
   `VctDefenseResult { kind: 'vcf' | 'vct' | ''; chain: string[]; points: string[]; tried: number }`）：
   先算对手的链 —— 有 VCF（7 ply）就用它，否则算含活三逼迫的 VCT（9 ply）；没有链则返回空。
2. **候选点按「近到远」分三档枚举**（这是上面那张对照表选出来的）：
   ① 链上各点（对手链首在最前）→ ② 这些点的**车氏 ≤2 邻域** → ③ `nearEmpties` 全部邻近空点
   按「到链的最短距离」升序。上限 `VCT_DEF_MAX = 12` 个点（`tried` 会记下实际试了几个）。
3. **判据比 `vcfDefense` 严一档**：落子后要求对手**既无 VCF(7) 也无 VCT(9)**，外加「对手没有
   一手成五」的兜底。`vcfDefense` 只要求「对手没有纯冲四链」—— 对手那条混合链正是从这道缝里进来的。
4. **并列拆法按 1-ply 取势排序**：命中点在「模型候选表里优先」，其次按
   `pressureOf`（对手造四点 ×2 + 活三点，越小越好）升序，收集到 `VCT_DEF_KEEP = 3` 个即停。
   理由：实测有「连拆六条链仍被穿透」的局，随手拆一个常把主动权交回去；取势排序不额外花钱
   （整套判定已经算过落子后的盘面）。
5. **战术层新增两个事实**：`vct_win_opponent: string[]`（拆点，与 `vcf_win_opponent` 同语义）、
   `vct_chain_opponent: string[]`（对手那条链本身，链首在前，供面板/取证）；
   `ALL_MECH` / `MECHS` 变 **16 键**（加 `vctDefense`）。
6. **接管链在 `vcfDefense` 与 `live3Attack` 之间插入 `vctDefense`**，成**十三级**：
   `win → block → open4 → threat → vcfAttack → vctAttack → vcfDefense → vctDefense →
   live3Attack → live3Defense → parry → parry3 → parry4`。位置理由：对手的**强制胜**比我们先手
   造活三（4 手剑）快；但纯冲四链一旦已有拆点，仍按老路走（`vcfDefense` 在前），保证
   「只补上新看见的那些局面」。
7. **闸门**：`engine.deepTactics && typeof engine.vctDefense === 'function' && win.length === 0 &&
   block.length === 0 && oppSide && M.vctDefense && res.vcf_win_you.length === 0 &&
   res.vct_win_you.length === 0 && res.vcf_win_opponent.length === 0`
   —— 即**我方没有 VCF/VCT 必胜链、`vcfDefense` 也没找到拆点**时才算。开火率因此受限于
   「我方无杀而对手有链」的回合占比（实测 ≤11%），不会去覆盖任何一层已有的必胜/必拆判断。
8. **登记表加第 13 行 `v12-vct-def`**（`rank 12`、机制 = v11 全开 + `vctDefense`，单调不减），
   `CURRENT` 改指它；`index.html` 三处战术下拉加选项并移动「（当前）」。

## 代价与不做什么

- **开火率与成本**：只在「我方无杀而对手有链」的回合开火（实测占我方回合 ≤11%），
  每次最多 12 个候选点，每个候选点要两次搜索（`vcfWin(7)` + `vctWin(9)`）。逐手离线扫描的
  单回合成本见「验证」第 3 条；`vcfDefense` 已经拆掉的回合完全不进这一层。
- **救不回来的局面是多数**：漏掉的 15 手里 13 手**全盘候选都拆不掉**（点无回头路），
  `vctDefense` 只能救剩下那 2 手。真正的入口在更早的地方 —— 对手「造四点」的爬升期
  （杀棋前 4–6 手）我方还在抢自己的活三。
- **不做「压力闸门」**（对手造四点数压过我们时不要抢 `live3Attack`、改走削他造四点数的点）：
  证据已经有了（上面第 3 条的压力轨迹），但它会**改变进攻选择**，影响面远超一层防守，
  必须单独一版 + 单独 A/B。本版只做「已经算得出对手有强制胜」时的拆链，不碰「对手还没有链」
  的局面，回归面因此最小。
- **不改 `vcfDefense` 本身**（不把它升级成混合链判定）：那是 v9 就在的层，改了会同时改变
  v9 / v10 / v11 三档的行为，A/B 就不再是单变量。新增一层、老层原样保留。
- **不做**时间预算 / 并行搜索 / 置换表：同一局面在不同机器上必须给出同一答案，否则对照实验
  的确定性没了（沿用 ADR-0015 的取舍）。
- **不做**「拆链优先于自己造杀」的例外：闸门已经保证「我方有必胜链时先赢」，拆链只在
  「算不出杀」时才发生。

## 验证

1. **夹具（回归用真实棋谱）**：`test/engines/tactics.test.mjs` ⑤d 五例，夹具 = 归档局
   `f463acff-b01c-4ef6-815f-b4b607d8fb94`（计时轮，`rapfi` 执黑 vs `proxy/v11` 执白，27 手黑胜）
   前 23 手，轮白走：第 24 手实走 `I11/parry`，而 `I11` 正是对手（黑）的**链首**
   （`vcfWin(black, 7).first = 'I11'`，黑走 `I11` 成双活四 = 必胜）。
   - 引擎层：`vctDefense(white, 9)` → `kind = 'vcf'`、`chain = ['I11']`、`points = ['K9']`、
     `tried = 12`（≤ `VCT_DEF_MAX`）；
   - **反例**：白只占链首 `I11` 之后，黑**仍有** VCF 与 VCT（`true / true`）——这就是当天实走那手的
     缺陷；而走 `K9` 之后黑**两样都没有**；
   - 档位差异：v11 档 `vct_win_opponent = []`、`vcf_win_opponent = []`（两样都看不见，
     `I11` 只被当成普通 `danger_points_opponent` → `parry`）；v12 档
     `vct_win_opponent = ['K9']`、`vct_chain_opponent = ['I11']`，`live3_you` 与 v11 逐字相同；
   - 决策级：模型给 `I11` 0.6 的概率，v11 档走 `I11/parry`，v12 档走 `K9/vctDefense`
     且 `meta.tacticsVersion = 'v12-vct-def'`；
   - **闸门**：在「我方有 VCF 必胜链」的局面上（`VCF_SEQ`），v12 的 `vct_win_opponent` /
     `vct_chain_opponent` 必须为空（先赢再说，不为防守多花一次搜索）。
2. **全量**：`node test/engines/run.mjs` **135 例全过**（原 130，+5）；金样逐手差分不变
   （自对弈 1131 手 + 归档 54 局 4379 手逐手一致）；`npx vitest run` 34 文件 / 337 例全过；
   `npx tsc --noEmit` 0 错。
3. **回归风险扫描**（`.work/v12-regression.mjs`，把已归档的三轮 proxy 棋谱逐手用 v12 重算，
   回答用户「过一下已有棋谱、看优化是否有回归降低能力的风险」）：**36 局 / 983 个 v11 回合**，
   其中「我方无杀而对手有链」（防守机会）**118 手**，`vcfDefense`（老层）已经认领 **51 手**，
   `vctDefense` **开火 13 手**（占全部回合 1.3%、占防守机会 11%）：
   - **真救 3 手**（实走没拆掉、v12 给的点能拆）：计时轮 `f463acff` ply24 实走 `I11/parry`
     → v12 给 `K9`；直连轮 `d879b7bc` ply50 实走 `J5/parry` → 给 `H5`；
     直连轮 `986185dc` ply18 实走 `G10/live3Defense` → 给 `F9`。
   - **本就拆掉 10 手**（实走也已经拆掉了对手的链，v12 只是同样能拆）：改了但无害 —— 这一档
     说明开火不等于改坏，归档那手本来就是对的。
   - **拆不掉 0 手**：没有任何一次开火给出「其实拆不掉」的点（判据是逐点试走复搜，
     只有对手 VCF 与 VCT 都没了才算）。
   - **攻击侧零影响**：983 个回合里「我方有必胜链」的 **163 手**不变 —— 闸门要求
     `vcf_win_you` / `vct_win_you` 为空，v12 不与任何必胜层抢。
   - 口径说明：扫描里「防守机会」用「对手有链且我方没有 VCF/VCT 链」定义，会多算极少数
     「我方一手成五即可赢」（`win` 层）的回合（计时轮 2 手），真实防守机会略低于 118。
4. **代价（同一批 983 个回合，含全部十三层）**：战术层耗时中位 **155 ms** / 均值 **247 ms** /
   p90 **605 ms** / 最坏 **4474 ms**；**开火的 13 个回合**中位 **1080 ms** / 均值 1534 ms
   （最坏即 4474 ms，发生在直连轮 `d879b7bc` ply22 这种双方都在织网的深局面）。
   即：不开火时这层几乎不花钱（闸门在算对手的链之前就要先确认我方无杀），开火时才付
   12 个候选点 × 2 次搜索的钱。

5. **对照实验（`v12-vct-def` vs `rapfi@500ms`，12 局黑白交替，tag `exp-20261002115126`）**：
   **12 胜 0 和 0 负（得分率 = 不败率 100%，执黑 6-0-0 / 执白 6-0-0，平均 33 手）**，
   逐版对比 v9 25% → v10 67% → v11 75~83% → v12 100%。
   **但本 ADR 的新机制在这一轮 0 次开火**：198 个 Jev 回合里我方有必胜链 78 手、对手有链的
   防守机会 42 手，实走 42/42 全拆掉，全部由既有层（`vcfDefense` / `block` / `parry`）完成 ——
   这个 12-0 是攻击层与老防守层打出来的，`vctDefense` 的实证仍是上面第 3、4 条的离线扫描与夹具。
   实战成本：`tac_ms` 中位 241 ms / 均值 381 ms / p90 896 ms / 最坏 4161 ms，单步墙钟均值 1029 ms
   ⇒ 战术层占单步均值 **37.0%**（上游本轮极快所致，不是战术层变慢：均值 402 → 381 ms）。
   ⇒ 结论：按 m08704 的口径，胜率已逐版稳步上升，**下一轮抬高 Rapfi 思考档（1000 ms 起）**，
   `vctDefense` 要等更强的对手才会被真正检验。

6. **抬高思考档后的两轮（按 m08704 执行，2026-10-02）**：
   - `rapfi@1000ms`（tag `exp-20261002121700`，12 局）：**10 胜 0 和 2 负（83.3%）**，执黑 6-0-0 / 执白 4-0-2，
     平均 40 手；239 个 Jev 回合里 `vctDefense` **开火 1 次**（它给了点、我们走了别的点，实走也把链拆掉了），
     真救 0、拆不掉 9（两局负局，逐条「全盘没有拆点」，且两局全程「我方有杀 0」）；
     `tac_ms` 中位 285 / 均值 695 / p90 1300 / 最坏 6843 ms ⇒ 战术层占单步均值 51.6%。
   - `rapfi@2000ms`（tag `exp-20261002123631`，12 局）：**7 胜 1 和 4 负（62.5% / 不败率 66.7%）**，
     执黑 4-0-2 / 执白 3-1-2，平均 60 手，并首次出现 **225 手满盘和棋**；363 个 Jev 回合里
     `vctDefense` **实走即拆点 1 次**（实走正是它给的点，链确实被拆掉），真救 0、拆不掉 14，
     四局负局全程「我方有杀 0」；`tac_ms` 中位 257 / 均值 815 / p90 2910 / 最坏 5362 ms ⇒ 占单步均值 54.0%。
   - **合起来的判定**：本 ADR 的机制**确实能在实战里给出有效拆点**（两轮各命中 1 次），
     但**五轮累计真救为 0** —— 从未出现「不靠它就会输」的回合；败局的一律形态是
     「算不出强制胜 + 全盘没有拆点」。⇒ 本层是「堵住最后一个可救点」的保险，
     不是强度杠杆；强度杠杆是压力闸门（下一版），继续加深搜索既无收益也违反
     「战术层不吃搜索」的约束。

## 对既有 ADR 的处置

- ADR-0015（v11 VCT）**保持原文不改**，作为历史记录；本 ADR 是它的直接后继：v11 补的是
  「把活三当逼迫手算进**我自己的**必胜链」，v12 补的是「把对手同样的混合链**拆掉**」。
  机制仍是逐版累加（v12 的 16 键 ⊇ v11 的 15 键），没有回退任何一层。
- ADR-0014（v10 活三真推演）里被 ADR-0015 收紧的那句仍然有效：活三的正确性质是**逼迫**，
  不是「4 手内必胜」。
