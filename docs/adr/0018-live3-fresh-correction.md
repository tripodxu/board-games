# ADR-0018：活三判据纠偏（`live3Fresh`）——L3 制造点必须由这一手新造，修正 0014 的 L3 定义

- 状态：accepted（2026-10-03）
- 背景：ADR-0014 把 **L3 活三制造点**定义为「落子后 **L2 的个数 ≥ 2**」。这个定义漏了一句
  本该有的前提：**那些 L2 点是这一手新造出来的**。于是只要本方**本来**就握着 ≥2 个活四制造点，
  **任何一步闲棋**（哪怕下在棋盘另一端、与三条毫不相干）都会被判成「制造活三」。
  这不是理论上的边角情况——它自 v10 上线起一直在给注入模型写事实、也一直在参与接管判定。

  实测（`.work/v14-live3-correct-scan.mjs`，五轮 Rapfi 对照共 **3864 个我方回合**，
  用独立实现逐回合交叉核对）：

  | 口径 | 数字 |
  | --- | --- |
  | 引擎口径非空回合 | 1648（42.7%） |
  | 其中「整集全是幻影点」的回合 | 16（占非空 **1.0%**） |
  | 引擎报出的制造点 | 18675 个 |
  | 其中幻影点（这一手什么都没新造） | **12676 个（67.9%）** |
  | 纠正口径漏报 | **0**（引擎集恒为纠正集的超集） |

  夹具级最小复现（`test/engines/tactics.test.mjs` ⑤f 夹具 A：黑 D1/E1/F1 活三、白远处三散子）：
  旧口径 `live3Makers(black)` = **28 个点**，含活三两端点，也含 `D3` 这种与三条无关的闲棋；
  纠正口径 = **0 个点**（这一手什么都没造）。

## 决定

1. **给 L3 加上「新造」前提**：L3 制造点 = 落子后**新造** ≥2 个 L2 点的点。
   实现为「落子前基线集合」的差集：新增内部 `l2Set(board, p, cands): Set<number>`
   （键 `r * N + c`，收集落子后 ≥2 成五点的位置），`live3After(board, p, r, c, cands, before?)`
   有基线时跳过基线内的点，`live3Count(board, p, cands, limit, fresh?)` 内部只算一次基线再摊到各候选。
2. **口径做成显式选项，缺省仍是旧口径**：`src/core/types.ts` 新增
   `Live3Options { fresh?: boolean }`，`live3Makers(st, sideId, opts?)` 与
   `live3Deny(st, sideId, candNotations, opts?)` 收它。**不传 / `fresh: false` 与旧口径逐字一致**
   ⇒ v0–v13 的历史归因、归档回放、金样差分全部不变（夹具里有一条断言专门钉这件事）。
3. **战术层按档传参**：`src/core/tactics.ts` 的 `ALL_MECH` 增加第 18 个键 `live3Fresh`，
   live3 两段（`live3_you` / `live3_opponent` / `live3_deny_points`）按 `M.live3Fresh` 传 `{ fresh: true }`。
4. **登记表新增 `v14-live3-fresh`**（rank 14，机制继承 v13 + `live3Fresh`），`CURRENT` 指向它。
5. **`pressureOf` 刻意不动**（`src/core/engines/gomoku.ts:690`）：它用
   `fourMakeCount * 2 + live3Count` 给 `vctDefense` 的并列拆法排序，是**启发式排序**，
   既不是给模型看的事实、也不是接管判定，改它只会扩大回归面。

## 代价与不做什么

- **不加层、不加预算、不改接管链顺序**：仍是十四级、仍是同一套 `else if` 顺序；
  纠正口径的成本中位 **14 ms** / p90 24 ms / 最坏 66 ms（n=3864），与旧口径同量级，
  远小于一次 Jev 往返（约 1 s）——符合 `AGENTS.md` 规则 10「收紧预算、修语义偏差」的许可范围。
- **它改变的是「给模型看的事实」，不是「已经发生的决策」**：用归档的接管层标签复核
  （`.work/v14-live3-tac-scan.mjs`，同一批 3864 回合），`live3Attack` 真接管 289 手、
  `live3Defense` 122 手，**没有一手**落在幻影点上（411/411 纠正口径仍认）；
  78 手「实走落在幻影点」全部来自其它层或模型自选（`block` 36 / 无接管 33 / `win` 9）。
  被判据修正的回合是 **212 手（占我方回合 5.5%）**：其中无接管（模型自选）80 手、整集皆假 16 手。
- **不做**：不用新口径重算历史归档的归因；不把 `fresh` 应用到 `vctDefense` 的排序启发式；
  不为它加任何新的搜索深度或节点预算。

## 验证

- 引擎自检 **142 个用例全过**（新增 ⑤f 三例：幻影点、按档给事实、对照组逐字不变）；
  `npx tsc --noEmit` 0 错；`npx vitest run` **34 文件 / 338 例全过**；
  `npm run check:docs` 52 个 md / 348 个链接。
- 对照组（夹具 C：黑两条开放二、落子前基线为空）：旧口径 = 纠正口径 = `['C1','F1','G8','J8']`，
  且决策级 v13 / v14 两档都由 `live3Attack` 接管走同一点 ⇒ **真制造点上纠偏是恒等变换**。
- **线上部署生效验证**（`.work/v14-deploy-verify.mjs`，独立实现、从归档记法逐手重放，不复用引擎内部函数）：
  在部署后的对照轮 `exp-20261003035953`（`1.0.0+b6c6921`）上，本方 316 手里 live3 两层接管 **60 手**、
  **60/60 落在纠正口径内**、旧集与纠正集**不同 0 手**；事实面 316 回合里旧集非空 **184（58.2%）**、
  旧≠纠正 **22（7.0%）**、旧非空但纠正后为空 0、点数 **2481 → 972（幻影 60.8%）**
  ⇒ 线上确实在改「给模型看的事实」，而**一手决策都没改**（与离线 5.5% 同量级）。
- 对照实验（`v14-live3-fresh` vs `rapfi@1000ms`，单臂 12 局）：**9 胜 1 和 2 负**（不败率 83.3%），
  两负全程「我方有杀 0」⇒ 本版不宣称涨棋，详见
  [plans/2026-10-03-tactics-v14-fresh-live3.md](../plans/2026-10-03-tactics-v14-fresh-live3.md) §6。
- **抬档复核（`rapfi@2000ms`，单臂 20 局，tag `exp-20261003050139`，用时 3453 s、上游 760 次全 200）**：
  **9 胜 3 和 8 负**（不败率 60.0%，三个和局全是 225 ½手满盘）；战术层 `tac_ms` 中位 199 / 均值 627 /
  最坏 6441 ms（占单步均值 53.3%）。**失效模式与 1 s 轮完全一致**：8 个负局全部「我方有杀 0」，
  拆不掉的 34 手逐条「全盘没有拆点」⇒ 抬档只让对手变强，**没有暴露纠偏引入的新回归**
  （同档轮间方差 17.5 个百分点，跨档位比分不是曲线）。

## 对既有 ADR 的处置

- **修正 0014 的 L3 定义**：0014 写的「落子后 L2 的个数 ≥ 2」应读作「落子后**新造** ≥2 个 L2 点」；
  0014 记的引擎方法与成本结论（该方法 9–28 ms）不变。
- 0007–0013、0015–0017 **不受影响**：它们的判定都走各自的方法，且缺省口径未变。
