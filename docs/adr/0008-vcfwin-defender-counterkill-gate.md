# ADR-0008：vcfWin 增加守方反杀闸门（soundness 修复），撤回 ADR-0007 的「守方反击造杀不覆盖」论断

- 状态：accepted（2026-09-30）
- 背景：ADR-0007 §1 最后一条写「守方即时致胜点不可能因攻方落子新增（五连须同色），
  且入口要求双方无一步杀；守方反击造杀属 VCT 范畴，本搜索不覆盖」。**这个论断是错的**，
  它是 `search()` 在 `m.wins.length >= 2`（双杀）处直接返回胜而不检查守方状态的依据。
  错因：前半句只说了「攻方落子不会给守方新增致胜点」，但真实时序里**守方自己
  那手被迫的堵点**能给它造四——攻方造四 → 守方唯一合法应对是堵 → 堵完守方自己成四
  （活四两端皆空 = 2 个成五点）→ 守方下一手直接成五 → 攻方后面的双杀永远兑现不了。

## 证伪过程

1. **合成最小反例**（`test/run-tests.js` ⑫i）：黑 F2,F3,F4 + G5,H5,G6；白 F1 + C6,D6,E6。
   入口双方均无一步杀（旧引擎复现成功）。旧引擎给黑判胜 `line=F5,F6,E5`：
   黑 F5 成四 → 白堵 F6 → 白 F6 与 C6,D6,E6 接成四（另一端 G6 被黑占，
   **唯一成五点 B6**）→ 黑 E5 双杀（引擎见 wins≥2 直接判胜）。
   但真实时序：黑 E5 之前白先走 B6 即成五，攻方双杀是**兑现不了**的。
2. **实战实证**：`games/2026-09-30/gomoku-20260930025550.json`（Jev 执黑，19 手后投子），
   第 36 手 black L14、第 38 手 black I11 均带 `tactics=vcfAttack`——正是探针
   判定的两条伪胜链。**这修正了 MEMORY.md 此前「该局失利属 VCT 范畴，不在 VCF
   补丁范围内」的归因**：它是一个 A 类（模式/实现 bug）缺陷，不是 B 类（搜索深度/
   估值）差距。
3. **回放扫描**：4 局棋谱 190 个决策点 × 攻方 7 ply，旧引擎 `win=9 / valid=7 /
   FALSE=2`，修复后 `win=7 / valid=7 / FALSE=0`。

## 决定

1. **`search(pliesLeft, dWins)` 带守方即时致胜点参数**，在双杀短路**之前**加闸门：
   ```
   if (dWins.length && !(dWins.length === 1 && dWins[0][0] === m.r && dWins[0][1] === m.c)) continue;
   ```
   语义：守方有即时致胜点时，攻方这一手**必须占掉它**（一步只占一个点）。
   于是 `dWins.length >= 2`（如 ⑫j 守方活四两端）时该分支无解，链子被正确丢弃。
2. **守方致胜点只查过新落子的四线**：递归进入下一层前，守方新产生的致胜点只能
   经过它自己刚堵的那一点（攻方子进不了守方五连），故传
   `winsAfter(wr, wc, D)` 而非全盘扫。入口仍做**一次**全盘扫 `defenderWinsFull()`
   （`vcfWin` 是引擎公开接口，外部调用方不保证入口无一步杀）。
3. **禁手口径与攻方侧对齐**：黑守方的致胜点用 `exactFiveAt`（长连不算赢）、
   禁手堵点视为堵不住（攻方胜）；白守方无禁手。
4. **不改优先级、不改门槛**：vcfAttack/vcfDefense 在九级接管中的位置、
   `computeTactics` 的「仅 1-ply 为空时才跑」入口条件都不变。修复只让链子变**更少更真**。

## 代价与不做什么

- **可能漏判真胜**：若攻方有一条真链，但同时存在另一条不占守方反杀点的走法，
  闸门会把它剪掉。生产路径上这个代价为零——`js/jev-client.js` 的入口门控保证
  进 VCF 前双方都无一步杀，因此 `defenderWinsFull()` 在生产里恒返回空数组；
  闸门只在递归层（`winsAfter(wr,wc,D)`）起作用，那里守方的反杀点来自**它自己
  刚被迫落下的那一子**，是真实的时序约束。宁可少报一条链，不可错报一条。
- **不做完整 VCT**：活三后多应对、安静织网、反击造杀（即「先手被破后另起一手
  逼杀」）仍不覆盖。ADR-0007 §5 的定位不变。
- **不引入节点/耗时增长**：实测修复前后 `perCall` 均 0.38ms，151 个决策点上
  只少了 2 条伪胜（25550:L14 / 25550:I11）与 1 条伪胜自身的 vcfDefense，
  其余 7 条有效链全部保留。

## 验证

- ⑫i（SYNTHETIC-2 合成反例）：head 判 `win=true line=F5,F6,E5` → 修复后 `win=false`；
  同一局面白攻 B6 是根节点双四（A6/F6 皆空），两版都判 `win=true first=B6`——
  闸门不误杀真胜。
- ⑫j（SYNTHETIC-3 守方活四 2 反杀点）：head `win=true` → 修复后 `win=false`。
- ⑫a 基准真链 H7→I7→H4：两版都判 `win=true`，未退化。
- 把 `git show HEAD:js/games/gomoku.js` 覆盖回 `js/games/gomoku.js` 重跑全量自检，
  新用例如期红（`✗ 守方堵点造四反杀时不应判攻方胜（伪胜回归）`）——用例是有效守卫，
  不是恒真断言。
- 4 局棋谱探针：`win=7 valid=7 FALSE=0`；`games/2026-09-30/gomoku-20260930025710.json`
  第 18 手仍 `vcfDefense=E13`、`...025550.json` 第 58 手仍 `vcfDefense=D9`，
  原有的真破杀行为不退化。

## 对 ADR-0007 的处置

ADR-0007 的**决定本体仍然有效**（棋盘级 VCF 搜索、九级优先级、试走后复搜、
「不是完整 VCT」的定位），仅 §1 最后一条的理论依据被本篇推翻。已在其 §1 该条
末尾标注勘误并指向本篇。**教训**：把「推论」写进 ADR 的「决定」段、且不标注它
依赖的前提，是这次缺陷能存活一整轮实战复盘的直接原因——注释里的论断比代码更
长寿，而没人再去验证它。
