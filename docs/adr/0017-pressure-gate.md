# ADR-0017：战术层新增「压力闸门」（`v13-pressure-gate`：对手做四点压过我们时先削点）

- 状态：accepted（2026-10-02）
- 背景：ADR-0016 结尾把下一版的入口写成了「压力闸门」：**对手的做四点数在杀棋前 4–6 手就开始爬升，
  而我方那几手还在抢自己的活三**。本轮先把这个现象量化，再决定机制。
  1. **量化（`.work/v13-pressure-probe.mjs`，六轮 rapfi 对照共 1787 个 Jev 回合，逐手离线复算）**：
     归档标签为 `live3Attack` 的实走共 **205 手（占全部回合 11.5%）**；其中
     **39 手（19.0%，占全部回合 2.2%）在落子前对手的「做四手数」已经超过我们**
     （胜局 28 / 和局 3 / 负局 8）。这 39 手里，**实走之后对手仍握着 ≥2 个做四点（双四威胁 = 2 手胜）
     的有 37 手**；改用「贴着对手的做四点削」的点集，**37/39 能把对手的做四手数压得更低、0 手更差，
     平均 −1.87 个，双四威胁 37 → 7**，候选可用率 39/39。逐轮：`115126` 10/25、`121700` 10/46、
     `123631` 7/66、其余三轮各 4/22、4/29、4/17。
  2. **语义依据（沿用 ADR-0015 的修正）**：活三**不是**「4 手内必胜」（一个活三的两个 L2 端点互斥，
     实测真双威胁 0 次），它只是**逼手**；真正把局面推向失败的是对手密集的做四点。
     而我方**真强制胜**早被 `vcfAttack`（纯冲四链）与 `vctAttack`（混合链）接管
     ⇒ 让位给「削点」不会漏掉任何必胜。
  3. **不能只拦不削（第一版设计被推翻）**：`.work/v13-fixture-find.mjs` 用引擎真算复核 `v12@500ms` 轮，
     25 个「抢活三而对手做四点领先」的回合里有 5 个 `pressure_opponent > pressure_you`，
     但这 5 个回合的 `live3_deny_points` **全为空**（引擎 `live3Deny` 的候选与判据都比独立实现严）。
     即：**只把 `live3Attack` 拦下来，接手的是 parry 系，削不到对手压力**，探针里的 −1.87 复现不了。
     ⇒ 必须自带「削点」搜索，而不是靠下层的既有防守层。
  4. **削点怎么找（引擎侧 1-ply，不加深任何搜索）**：候选序 = 模型候选点 → 「对手做四点」的车氏 ≤2 邻域
     （按距离升序）→ 其余邻近空点；每个候选落子后量一次对手的做四手数，
     只有**严格低于落子前**才算削点，并列时取**自己做四手数更大**者。
     候选序是硬要求：`.work/v13-cut-debug.mjs` 实测按行序盲试时 `1be84659` ply24 的 `C8`
     （对手 6 → 4，全盘最优）落在第 40 个之后，被候选上限截掉，削点集成了空集。

## 决定

1. **引擎新增两个可选方法**：
   - `fourPressure(st, sideId, limit?): number` —— 某一方的「做四手数」= 空点数，落在那里就能造出一个冲四
     （`fourMakeCount` 的公开包装）。**默认不早退**（`limit = 99`）：早退会让两侧同时触顶，
     把「落后」误判成「不落后」。
   - `pressureCut(st, sideId, opts?): PressureCutResult` —— 返回
     `{ points: string[]; before: { you, opponent }; after: { you, opponent }; tried }`，
     `points` 为空 ⟺ 没有任何候选能严格压低对手的做四手数。
2. **候选序 = 模型候选 → 对手做四点的车氏 ≤2 邻域（按距离升序）→ 其余邻近空点**，
   上限 `PRESSURE_CUT_MAX = 120`（实测单次成本均值 4.0 ms / 中位 3 ms / 最坏 9 ms），
   并列保留 `PRESSURE_CUT_KEEP = 3` 个。**削点搜索不搜杀**：它只做 1-ply 手数量，
   既符合「战术层不吃搜索」，也不引入新的不确定性。
3. **战术层新增三个事实**：`pressure_you: number`、`pressure_opponent: number`（双方做四手数）、
   `pressure_cut_points: string[]`（削点）。`ALL_MECH` / `MECHS` 变 **17 键**（加 `pressureGate`）。
4. **压力计数与削点只在「我方没有一步致胜、也没有 2-ply 造杀/拆杀」时计算**（与 2-ply 块同一道前置闸门），
   且**削点只在 `pressure_opponent > pressure_you` 时才算** —— 不落后就不花这份钱，
   也不做无谓的「让攻势」。
5. **接管链在 `vctDefense` 与 `live3Attack` 之间插入 `pressureGate`**，成**十四级**：
   `win → block → open4 → threat → vcfAttack → vctAttack → vcfDefense → vctDefense →
   pressureGate → live3Attack → live3Defense → parry → parry3 → parry4`。
   位置理由：它要拦的正是「抢活三」那一步，而所有**强制胜/必拆**必须排在它前面（先赢、先堵死）。
6. **开火条件四条**：`M.pressureGate`（版本闸门）`&& pressure_cut_points.length`
   `&& pressure_opponent > pressure_you` `&& !danger_points_opponent.length`。
   **最后一条是安全线**：`.work/v13-*` 回归里 `test/engines/tactics.test.mjs` 的 p18 夹具
   （「双 danger 并存」）抓到过反例 —— 削点搜索只认手数、不认「对手下一步就有杀」，
   会挑出走子方偏好的那个危险点；加上这条守卫后它与 `live3Attack` 站同一条线，
   危险局面交回 `parry` / `safeSort`。
7. **削点为空则本层不开火** ⇒ 没有削点的局面行为与 v12 **逐字一致**（最小回归面）；
   这也是「先 implementation、再回归扫描、再 A/B」这条流程能给出单变量结论的前提。
8. **登记表加第 14 行 `v13-pressure-gate`**（`rank 13`、机制 = v12 全开 + `pressureGate`，单调不减），
   `CURRENT` 改指它；`index.html` 三处战术下拉加选项并移动「（当前）」。

## 代价与不做什么

- **真接管时会用攻势换安全**：三个 v12 回合的回归扫描（`.work/v13-cut-check.mjs`，800 个 Jev 回合）
  里「闸门真接管」**26 手** —— 对手做四手数**更优 14/26、平均 −1.08 个**，
  但我们自己的做四手数**平均 −1.92 个、13/26 让掉了自己的攻势**。
  典型案例（夹具 `e3e417e6` ply8）：实走 `E9/live3Attack` 后我方做四手数 4、对手 2；
  削点 `D12` 后对手 0、我方 0。**这是有意的取舍**（ADR-0015 已证明活三只是逼手，
  而输局的一律形态是「算不出强制胜 + 对手压力爬升」），但它确实改变了进攻选择，
  必须由同口径 A/B 判定，不能只看离线指标。
- **不加深搜索**：候选上限 120 只是「多试几个点」，每个点一次 1-ply 计数；
  与 v11 的「最坏 4.6 s 同步阻塞」不是同一类风险（实测最坏 9 ms）。
- **不改 `live3Attack` / `live3Deny` / `live3After`**：ADR-0015 已判定 `live3After` 的
  「盘面任意 L2 点」口径是缺陷，但改它会同时改变 v10/v11/v12 三档行为，A/B 不再是单变量。
  本版只新增一层，老层原样保留。
- **不做**「对手压力领先就一律不进攻」的硬闸门（第一版设计）：它只拦不削，实测那 5 个回合
  的 `live3_deny_points` 全空，拦下来只会掉到 parry 系。
- **不做**时间预算 / 并行 / 置换表：同一局面在不同机器上必须给出同一答案（沿用 ADR-0015/0016 的取舍）。

## 验证

1. **夹具（回归用真实棋谱）**：`test/engines/tactics.test.mjs` ⑤e 四例，夹具 = 归档局
   `e3e417e6-1f3c-4f52-baa3-3234ddd0159c`（v12 单臂 `exp-20261002115126`，`rapfi` 执黑 vs
   `proxy/v12` 执白，白方五连胜）前 7 手，轮白走：
   - 引擎层：`fourPressure(white) = 0`、`fourPressure(black) = 2`；`pressureCut(white, { cands: [] })`
     → `points` 含 `D12`、`before.opponent = 2`、`after.opponent = 0`、`tried ≤ 120`；
     **反例**：实走的 `E9` 之后对手仍是 2（没削到）。
   - 闸门：同一局面退到前 6 手（轮黑，黑 2 个做四点、白 0 个）⇒ 走子方**不落后**，
     `pressure_cut_points = []`（不花这份钱）。
   - 档位差异：v12 档 `pressure_cut_points = []` 且 `live3_you` 非空（本来要抢活三）；
     v13 档报出 `pressure_you = 0` / `pressure_opponent = 2` / 削点 `['D12', 'C13']`，
     `live3_you` 与 v12 逐字相同（机制单调不减）。
   - 决策级：模型给 `E9` 0.6 概率，v12 档走 `E9/live3Attack`，v13 档走 `D12/pressureGate`
     且 `meta.tacticsVersion = 'v13-pressure-gate'`。
2. **全量**：`node test/engines/run.mjs` **139 例全过**（原 135，+4）；金样逐手差分不变
   （自对弈 1131 手 + 归档 54 局 4379 手逐手一致）；`npx vitest run` 34 文件 / 337 例全过；
   `npx tsc --noEmit` 0 错。
3. **回归风险扫描**（`.work/v13-cut-check.mjs`，把已归档的三个 v12 回合逐手用 v13 重算，
   回答用户「过一下已有棋谱、看优化是否有回归降低能力的风险」）：**800 个 Jev 回合**，
   「条件满足」（有削点且压力落后）**78 手（9.8%）**，其中**闸门真能接管 26 手（3.3%）**，
   其余 52 手被更高层挡住（`vcfDefense` 40 / `parry4` 7 / `vcfAttack` 5 / `open4` 3 / `vctAttack` 3
   / `vctDefense` 1）——**不是漏杀，是优先级正确**。
   - **收益**：78 手里对手做四手数更优 24 / 持平 54 / **更差 0**，平均 −0.69 个；
     双四威胁（≥2）**45 → 30**。真接管的 26 手里更优 14 / 持平 12 / 更差 0，平均 −1.08 个。
   - **代价**：真接管的 26 手里我们自己的做四手数平均 **−1.92 个**、13 手让掉攻势（见上）。
   - **攻击侧零影响**：闸门只在「我方没有一步致胜、也没有 2-ply 造杀/拆杀」且**没有任何
     必胜/必拆层给点**时才开火，因此不与 `win` / `block` / `vcf*` / `vct*` 任何一层抢。
   - 逐轮：`exp-20261002115126` 198 回合 / 条件满足 25（12.6%）/ 真接管 7；
     `exp-20261002121700` 239 / 21（8.8%）/ 6；`exp-20261002123631` 363 / 32（8.8%）/ 13。
4. **成本**：`pressureCut` 单次均值 **3.2 ms** / 中位 3.3 ms / 最坏 **6.1 ms**（n = 78，
   含 120 个候选点的完整一轮；口径分层后重跑，见 `.work/v13-cut-check.log`）；
   不开火时这层不花任何搜索（闸门在算削点之前先看压力对照）。

5. **对照实验（2026-10-03 已完成）**：`rapfi@1000ms` 档 12 局 **9 胜 0 和 3 负（75.0%）**，
   v12 同档 **10 胜 0 和 2 负（83.3%）** —— 一局之差在 12 局样本里是噪声，**比分口径在这轮无效**。
   决定性证据是接管标签 × 局结果的交叉表：四个进攻类层（`vctAttack` / `open4` / `win` /
   `vcfAttack`）在 9 个胜局合计命中 79 手、3 个负局命中 **0 手**，三局负局「我方有杀」全为 0
   ⇒ **输在「赢不了」而不是「防不住」**。**判定：机制按设计工作（对手做四手数确实降、双四威胁
   确实减、单次 3.2 ms）但不是当前瓶颈 ⇒ 保留、不再加码**，下一版转向进攻侧。
   完整数字与逐局表见 `docs/plans/2026-10-02-tactics-v13-pressure-gate.md` §6。
6. **20 局档位复核（2026-10-03，`docs/plans/2026-10-02-tactics-v13-pressure-gate.md` §6.7）**：
   `rapfi@1000ms` 20 局 **11 胜 1 和 8 负（57.5%）**、`rapfi@2000ms` 20 局 **13 胜 2 和 5 负（70.0%）**；
   同档合并 `v13@1000ms` = **32 局 20 胜 1 和 11 负（64.1%）**。
   ⚠️ 同档两轮差 17.5 个百分点 > 档位之间的差 ⇒ **比分仍由上游采样方差主导**（这也是把
   「逐版胜率稳步上升」当作抬档前提时必须先承认的口径限制）；`vctDefense` 两轮合计开火 3 次、
   真救 0，仍未被实战检验。逐手复盘：两轮 24 + 16 个「拆不掉」回合**全部是「全盘没有拆点」**
   （已经输了的局面），与七轮以来的形态一致。

## 对既有 ADR 的处置

- ADR-0016（v12 `vctDefense`）**保持原文不改**，本 ADR 是它的直接后继：
  ADR-0016 结尾把「压力闸门」列为不做（影响面大、必须单独一版），本 ADR 正是那一版。
- ADR-0015（v11 VCT）的语义修正仍然是本 ADR 的立论基础：活三只是逼手，不是杀。
- 机制逐版累加：v13 的 17 键 ⊇ v12 的 16 键，没有回退任何一层。
