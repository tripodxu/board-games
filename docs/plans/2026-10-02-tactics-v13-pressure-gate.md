# 计划与执行记录：战术 v13 `v13-pressure-gate`（压力闸门 / 削对手做四点）与 Rapfi 对照实验

- 状态：**机制已验证但判定为「不治瓶颈」，保留不加码**（2026-10-03：对照实验已跑完，见 §6；结论见 §7，
  下一版方向改为进攻侧，见 §9）
- 触发：用户在 v12 交付后重申目标（m08704）：「根据所有跑的有价值的实验整合出下一版本的战术优化，
  并过一下已有的棋谱信息，不一定要全量，看看优化是否有回归降低能力的风险，之后再与rapfi跑，
  当胜率多版本稳步上升之后，提高rapfi的思考时间，不要忘记写实验报告和文档的更新优化工作，如此迭代」
  —— 本计划只覆盖其中「下一个版本」这一轮。

## 1. 目标

1. **整合已有实验**：v12 跑完三档 Rapfi（0.5 s / 1 s / 2 s）后，五轮对照的一致败局形态是
   「**我方有杀 0 + 全盘没有拆点**」⇒ 下一版的入口不在「再挖一层防守」，而在
   **对手压力爬升期不要抢自己的活三**（ADR-0016 结尾列为「不做，下一版再说」的那件事）。
2. **过已有棋谱看回归风险**：把三个 v12 回合逐手用 v13 重算，量化「会改掉多少手、改对多少手、
   代价是什么」，再决定这一版做不做、做多大。
3. **优化**：给出第十三版战术（登记表第 14 行 `v13-pressure-gate`），机制变化要能用数字说清
   「削掉的是哪一类压力」。
4. **实验**：`v13-pressure-gate` vs Rapfi，与前几版**同对手、同开局、同局数**口径对比；
   v12 在 0.5 s 档已 12-0（打满），本轮起以 **1 s 档**为主对照档（v12 在同档是 10-0-2 = 83.3%）。

### 2.2 败局形态五轮一致

六局负局（1 s 档 2 局 + 2 s 档 4 局）**全程「我方有杀 0」**，逐手复算的「拆不掉」逐条都是
**全盘没有拆点**（`.work/v12-round-postmortem.mjs`）⇒ 输在「算不出强制胜」+「对手压力已经成型」。

### 2.3 压力探针（`.work/v13-pressure-probe.mjs`，六轮共 1787 个 Jev 回合）

- 归档标签 `live3Attack` 实走 **205 手（11.5%）**；
- 其中 **39 手（19.0%）落子前对手做四手数已超过我们**（胜 28 / 和 3 / 负 8）；
- 这 39 手实走之后**对手仍握双四威胁（≥2 个做四点）的 37 手**；
- 改用「贴着对手做四点削」的点集：**37/39 更优、0 更差、平均 −1.87 个，双四威胁 37 → 7**。

### 2.4 为什么不能「只拦不削」（第一版设计被推翻）

`.work/v13-fixture-find.mjs` 用引擎真算复核 `v12@500ms` 轮：25 个「抢活三而对手做四点领先」的回合里
5 个满足 `pressure_opponent > pressure_you`，但 **`live3_deny_points` 全为空**
（引擎 `live3Deny` 的候选与判据都比独立实现严）⇒ 只把 `live3Attack` 拦下来会掉到 parry 系，
削不到对手压力，探针的 −1.87 复现不了。**必须自带削点搜索。**

## 3. 设计（详见 [ADR-0017](../adr/0017-pressure-gate.md)）

- 引擎：`fourPressure(st, sideId, limit?)`（做四手数，默认不早退）+ `pressureCut(st, sideId, opts?)`
  （1-ply 削点搜索，`PRESSURE_CUT_MAX = 120` / `PRESSURE_CUT_KEEP = 3`）。
- 候选序：模型候选 → 对手做四点的车氏 ≤2 邻域（按距离升序）→ 其余邻近空点。
  **候选序是硬要求**：行序盲试会把 `1be84659` ply24 的最优削点 `C8`（对手 6 → 4）挤出上限，削点集变空集。
- 战术层：新增 `pressure_you` / `pressure_opponent` / `pressure_cut_points` 三个事实，
  `ALL_MECH` 17 键；削点只在「压力落后」时算。
- 接管链：在 `vctDefense` 与 `live3Attack` 之间插 `pressureGate`，成**十四级**。
- 开火条件四条：版本闸门 + 有削点 + 压力落后 + **对手没有 danger 点**（安全线，见 ADR-0017 决定 6：
  p18 夹具抓到过「只认手数、不认对手下一步的杀」的反例）。
- 削点为空则不开火 ⇒ 与 v12 逐字一致（最小回归面）。

## 5. 验证证据

- `test/engines/tactics.test.mjs` ⑤e 四例（夹具 = 归档局 `e3e417e6` 第 8 手，见 ADR-0017「验证」）。
- `node test/engines/run.mjs` **139 例全过**（原 135，+4）；金样逐手差分不变（自对弈 1131 手 +
  归档 54 局 4379 手逐手一致）；`npx vitest run` 34 文件 / 337 例全过；`npx tsc --noEmit` 0 错。
- 回归风险扫描（`.work/v13-cut-check.mjs`，逐手用 v13 重算三个 v12 回合）。
  **2026-10-03 重跑并把口径拆成三层**：原版把「有削点且压力落后」（= 闸门**有机会**开火）和
  「闸门真接管」（前八层全空 = **真会改变行为**）混在同一个 `fire` 计数里，输出里
  「削点与实走同点 42 / 真接管 26」看着互相矛盾。现在三层分别是：
  - **条件满足**（`meet`，78 手 / 9.8%）：压力落后且引擎算出了削点，**不等于会改走**；
  - **闸门真接管**（`reach`，26 手 / 3.3%）：条件满足 **且** 接管链前八层全空 —— 唯一真会改变行为的样本；
  - **真接管且改走**（`changed`，20 手 / 2.5%）：真接管的子集，且削点首选 ≠ 实走。
    这是「本来就走对了、却被我们换掉」的那一半，与 `reach` 之差（26 − 20 = 6）就是没被动过的部分。
  - 被更高层挡住 52 手（`vcfDefense` 40 / `parry4` 7 / `vcfAttack` 5 / `open4` 3 / `vctAttack` 3 /
    `vctDefense` 1 —— **优先级正确，不是漏杀**）；
  - **收益（全部 78 个条件满足回合）**：对手做四手数 **更优 24 / 持平 54 / 更差 0**、平均 −0.69；
    双四威胁 **45 → 30**；我们自己的做四手数平均 **−0.18 个**；
  - **收益（只算 26 个真接管回合）**：对手做四手数 **更优 14 / 持平 12 / 更差 0**、平均 **−1.08 个**；
  - **代价（只算 26 个真接管回合）**：我们自己的做四手数 **平均 −1.92 个**、13 手让掉攻势（有意的取舍）。
    ⚠️ 两个均值样本不同（78 vs 26），**不可并列比较**；
  - 攻击侧零影响：不与 `win` / `block` / `vcf*` / `vct*` 任何一层抢；
  - 成本：`pressureCut` 单次均值 **3.2 ms** / 中位 3.3 / 最坏 6.1 ms（n = 78）。
    （2026-10-03 重跑的实测值比首轮记的 4.0 / 9 ms 更准：脚本从 `Date.now()` 换成
    `performance.now()`，毫秒级抖动被消掉了。同一份结果里 `changed` 汇总 20 手正确，
    但**逐轮小计一开始漏了 `t.changed++`** 导致三轮都印「改走 0」，已修；这就是上一版
    「同点 42 / 真接管 26 看着矛盾」的真正来源 —— 42 是 78 个条件满足回合里的同点数，
    26 是真接管数，两个口径本来就不同层。）
- 逐轮（重跑）：`115126` 198 回合 / 条件满足 25（12.6%）/ 真接管 7 / 其中改走 5；
  `121700` 239 / 21（8.8%）/ 6 / 改走 6；`123631` 363 / 32（8.8%）/ 13 / 改走 9。
  改走率随对手变强而升（500 ms 档 5/7 → 1 s 档 6/6 → 2 s 档 9/13），
  即**这道闸门在越强的对手下越会真正介入**（v13 的行为变化面集中在高档）。
  证据 `.work/v13-cut-check.log`（当前口径）、`.work/v13-cut-check-layered.log`（分层口径的同一次输出留档）。

## 6. 对照实验：`v13-pressure-gate` vs Rapfi（已完成 2026-10-03）

- 主对照档 **`rapfi@1000ms`**（v12 在同档是 10 胜 0 和 2 负 = 83.3%）；12 局黑白交替、同一开局面。
- **tag `exp-20261002160819`**，用时 3450 s，上游 335 次
  （in 805,491 / out 148,874 tok，HTTP 错 66 次**全部已重试成功**、页面错误 0、重试点击 0），
  Rapfi 资产本地供给 3 文件 / 10.7 MB。

### 6.1 战绩：9 胜 0 和 3 负（75.0% / 不败率 75.0%）

| 指标 | v12@1000ms | **v13@1000ms** |
| --- | --- | --- |
| 战绩 | 10 胜 0 和 2 负 | **9 胜 0 和 3 负** |
| 得分率 / 不败率 | 83.3% / 83.3% | **75.0% / 75.0%** |
| 执黑 / 执白 | 6-0-0 / 4-0-2 | **4-0-2 / 5-0-1** |
| 平均手数 | 40 | **45** |
| Jev 回合数 | 239 | 269 |

⚠️ **一局之差（75% vs 83.3%）在 12 局样本里落在噪声内**，两边 Wilson 区间大幅重叠。
**不能据此说 v13 变弱**，也不能据此说 v13 有用 —— 比分口径在这轮里是无效判据，必须看机制层。

### 6.2 决定性证据：接管标签 × 局结果的交叉表（`.work/v13-vs-v12-turns.mjs`）

| 接管层 | 9 个**胜**局命中 | 3 个**负**局命中 |
| --- | --- | --- |
| `vctAttack` | **50** | **0** |
| `live3Attack` | 16 | 13 |
| `vcfDefense` | 6 | 18 |
| `block` | 2 | 15 |
| `live3Defense` | 4 | 9 |
| `open4` / `win` / `vcfAttack` | 9 / 9 / 11 | **0 / 0 / 0** |
| `pressureGate`（v13 新层） | 8 | 6 |
| （无接管） | 41 | 39 |

⇒ **四个「进攻 / 直接取胜」类层（`vctAttack` / `open4` / `win` / `vcfAttack`）在 9 个胜局里
合计命中 79 手，在 3 个输局里命中 0 手**；三个负局的「我方有杀」也全是 0（败局体检 `.work/v13-postmortem.log`）。
**结论：这一轮输棋的原因不是「防不住」，是「赢不了」** —— v13 是纯防守机制，治不了这个病。

### 6.3 v13 机制本身的开火面（14 手）

开火 14 手，落在 8 胜 / 0 和 / 6 负的局里：`#1(L) ×1`、`#2(L) ×3`、`#5(L) ×2`、
`#7(W) ×4`、`#9(W) ×1`、`#12(W) ×3`。逐手看多数是**对手做四手数从 2 → 0** 的干净压制
（如 `7e568887 ply16 走 H15：我们做四 0 / 对手 2 → 落子后对手做四 0`），
但也有一手是**对手 6 → 4 仍留双四**（`d2c97ae4 ply27`，且该局负）。
**净效果：14 手把对手做四手数确实压下去了，但没有一局因此从负翻成胜**。

### 6.4 成本（v13 侧，n=269）

`tac_ms` 中位 230 / 均值 498 / p90 1027 / 最坏 **6046 ms**；单步墙钟中位 1077 / 均值 10093 ms；
战术层占单步均值 **4.9%**（逐手平均比例 27.1%）。
⚠️ 单步墙钟均值 10093 ms 是**上游重试**造成的（HTTP 错 66 次 ⇒ 模型往返均值 9595 ms、
p90 42008 ms），与战术层无关 —— 战术层占比因此被稀释到 4.9%（v12 同档是 51.6%）。
**报战术层占比时必须同轮同分母**，跨轮比这个数会得出完全错误的结论。

### 6.5 旁证：v12 侧那 5 手「该被改写」的活三，全落在胜局里

v12@1000ms 的 46 手 `live3Attack` 中，「落子前对手做四手数已超过我们」的只有 5 手，
且这 5 手**全部在胜局里**。这与 6.2 交叉表一致：**在被改写的那类回合上，v12 的抢攻没有害过它**。
⇒ 压力闸门的判据本身没有抓住「坏的手」，它抓住的是「一般情况下无害、偶尔让掉攻势」的手。

## 7. 结论与下一版方向（本轮 A/B 给出的答案）

1. **v13 的机制按设计工作**（对手做四手数确实降、双四威胁确实减），**但不是当前的瓶颈**：
   12 局对照下战绩 9-0-3 vs 10-0-2 属噪声内，机制开火的 14 手没有一手换来翻盘。
   ⇒ **v13 保留**（它不伤胜率、几乎零成本：`pressureCut` 3.2 ms），但**不再往上加码**。
2. **瓶颈是进攻侧**：四个进攻类层在胜局 79 手 / 输局 0 手（6.2）。这是 v13 结构上治不了的。
3. **下一版候选改为「把进攻提上去」**，且必须继续满足「不吃搜索 + 一眼看得懂的简单规则」：
   - `.work/v14-attack-probe.mjs`（已跑，见 §6.6）给出的答案是**第三种情况**：
     输局里既不是「有强制胜链没走」（漏杀 0），也不是「压根没牌」（两局负局的
     「有活三可造」只有 2 / 4 手，且**都已经被 `vcfDefense` / `vctDefense` 更高层正确接管**），
     而是 —— **进攻机会存在但「造的时机太晚」**。
   - 关键证据：三局负局的有杀数是 0，而**同一批负局里 `live3Attack` 命中 13 手**。
     `live3Attack` 造的是活三（逼手），它让对手有机会反打；
     而真正赢棋的局靠的是 `vctAttack`（连续威胁）**50 手**、**三次全部命中只在胜局**。
     ⇒ 结论不是「该多抢攻」，而是**「赢棋的手该走 `vctAttack` 而不是 `live3Attack`」**：
     活三是逼手不是杀（ADR-0015 已判定），负局的 13 手 `live3Attack` 很可能是输因之一。
   - 这指向 v14 的具体入口：**提高 `vctAttack` 的命中面**（它当前只在「已有连续威胁」时开火），
     而不是继续调 `live3Attack` 或压力闸门。

### 6.6 进攻侧探针结果（`.work/v14-attack-probe.mjs`，决定 v14 方向）

| 口径 | v13@1000ms（tag 160819） | v12@1000ms（tag 121700） |
| --- | --- | --- |
| Jev 回合 | 269 | 239 |
| 我方有杀（有强制胜链的回合） | 79 | 77 |
| **漏杀（有链却没走链首）** | **2** | **8** |
| 有活三可造却没造 | 18 | 11 |
| 有造杀点没走（`chance_points_you`） | **0** | **0** |

- **漏杀 2 手都在终局**（`ply46 实走 I6(win)` / `ply31 实走 G4(win)`）—— 已经是「赢了」的那一手，
  不是真漏杀（v12 的 8 手同理，`ply31 实走 G4(win)` 这类）。⇒ **漏杀不是问题**。
- **有造杀点没走 = 0**：说明 `live3Attack` / `vctAttack` 的接管链**没有漏掉已算出的牌**。
- **「有活三可造却没造」18 手全部被更高层正确接管**（`vcfDefense` / `pressureGate` / `vctDefense`）——
  不是漏杀，是优先级。⚠️ 但注意：`pressureGate` 出现 6 次、`vcfDefense` 12 次，
  说明**这些「本可抢攻」的时刻被判给了防守**，这与 6.2 的交叉表吻合（输局里只有防守类层命中）。
- ⇒ **负局的成因不是漏杀，是「进攻类层在负局根本没开火过」**。
  进攻类层（`vctAttack` / `open4` / `win` / `vcfAttack`）在胜局 79 手、负局 **0 手**。
  下一步要查的是：**为什么这些层在负局里不开火** —— 是没有可攻的形状，
  还是开火判据太严。探针已给出候选入口（见 §9 第 1 条）。

## 8. 未闭环

1. **「用攻势换安全」是否划算**已由本轮 A/B 回答：**12 局里分不出来**（9-0-3 vs 10-0-2 属噪声内），
   但 6.2 的交叉表说明代价是**真实存在的**（进攻类层在输局 0 手命中）。要拿到统计显著的结论，
   需要更大样本（≥ 50 局 / 档），而不是继续在同一口径下赌一局之差。
2. **`live3After` 的缺陷仍在**（ADR-0015 判定「盘面任意 L2 点」口径不对，`live3Deny` 因此常空）——
   本版没改它（改它会同时改变 v10/v11/v12 的行为，A/B 不再是单变量）。
   ⚠️ 但 6.5 已经显示「`live3Attack` 的保守判据」是需要复查的对象，这条的优先级因此上升。
3. **`danger_points_opponent` 这条安全线是启发式**：它来自引擎 criteria，不是「对手下一步必胜」的证明；
   实测 p18 那类局面靠它挡住，但更细的判据（逐点试走验杀）会贵一个量级。
4. **战术层最坏值仍受上游重试影响**：本轮 66 次 HTTP 错把模型往返均值抬到 9595 ms、
   单步墙钟 p90 42008 ms、最坏 46296 ms（战术层本身最坏只有 6046 ms）。
   ⇒ **重试率高的轮次里，「战术层占单步比例」会被稀释到失真**（本轮 4.9% vs v12 同档 51.6%），
   跨轮比这个数没有意义。

## 9. 下一版候选（2026-10-03 A/B + 进攻探针后重排，按证据强度排序）

1. **进攻类层在负局不开火的原因（v14 的入口，证据最硬）**：交叉表（6.2）+ 探针（6.6）合起来说
   「负局里进攻类层 0 命中」，探针排除了漏杀（漏杀 2、造杀点没走 0），所以只可能是
