# 计划与执行记录：战术 v13 `v13-pressure-gate`（压力闸门 / 削对手做四点）与 Rapfi 对照实验

- 状态：**进行中**（2026-10-02：机制 / 实现 / 单测 / 回归扫描已落地；对照实验与文档回填见 §6）
- 触发：用户在 v12 交付后重申目标（m08704）：「根据所有跑的有价值的实验整合出下一版本的战术优化，
  并过一下已有的棋谱信息，不一定要全量，看看优化是否有回归降低能力的风险，之后再与rapfi跑，
  当胜率多版本稳步上升之后，提高rapfi的思考时间，不要忘记写实验报告和文档的更新优化工作，如此迭代」
  —— 本计划只覆盖其中「下一个版本」这一轮。

## 1. 目标

1. **整合已有实验**：v12 跑完三档 Rapfi（0.5 s / 1 s / 2 s）后，五轮对照的一致败局形态是
   「**我方有杀 0 + 全盘没有拆点**」⇒ 下一版的入口不在「再挖一层防守」，而在
   **对手压力爬升期不要抢自己的活三**（ADR-0016 结尾列为「不做，下一版再说」的那件事）。
2. **过已有棋谱看回归风险**：把三个 v12 回合逐手用 v13 重算，量化「会改掉多少手、改对多少手、
   代价是什么」，再决定这一版做不做、做多大。
3. **优化**：给出第十三版战术（登记表第 14 行 `v13-pressure-gate`），机制变化要能用数字说清
   「削掉的是哪一类压力」。
4. **实验**：`v13-pressure-gate` vs Rapfi，与前几版**同对手、同开局、同局数**口径对比；
   v12 在 0.5 s 档已 12-0（打满），本轮起以 **1 s 档**为主对照档（v12 在同档是 10-0-2 = 83.3%）。

### 2.2 败局形态五轮一致

六局负局（1 s 档 2 局 + 2 s 档 4 局）**全程「我方有杀 0」**，逐手复算的「拆不掉」逐条都是
**全盘没有拆点**（`.work/v12-round-postmortem.mjs`）⇒ 输在「算不出强制胜」+「对手压力已经成型」。

### 2.3 压力探针（`.work/v13-pressure-probe.mjs`，六轮共 1787 个 Jev 回合）

- 归档标签 `live3Attack` 实走 **205 手（11.5%）**；
- 其中 **39 手（19.0%）落子前对手做四手数已超过我们**（胜 28 / 和 3 / 负 8）；
- 这 39 手实走之后**对手仍握双四威胁（≥2 个做四点）的 37 手**；
- 改用「贴着对手做四点削」的点集：**37/39 更优、0 更差、平均 −1.87 个，双四威胁 37 → 7**。

### 2.4 为什么不能「只拦不削」（第一版设计被推翻）

`.work/v13-fixture-find.mjs` 用引擎真算复核 `v12@500ms` 轮：25 个「抢活三而对手做四点领先」的回合里
5 个满足 `pressure_opponent > pressure_you`，但 **`live3_deny_points` 全为空**
（引擎 `live3Deny` 的候选与判据都比独立实现严）⇒ 只把 `live3Attack` 拦下来会掉到 parry 系，
削不到对手压力，探针的 −1.87 复现不了。**必须自带削点搜索。**

## 3. 设计（详见 [ADR-0017](../adr/0017-pressure-gate.md)）

- 引擎：`fourPressure(st, sideId, limit?)`（做四手数，默认不早退）+ `pressureCut(st, sideId, opts?)`
  （1-ply 削点搜索，`PRESSURE_CUT_MAX = 120` / `PRESSURE_CUT_KEEP = 3`）。
- 候选序：模型候选 → 对手做四点的车氏 ≤2 邻域（按距离升序）→ 其余邻近空点。
  **候选序是硬要求**：行序盲试会把 `1be84659` ply24 的最优削点 `C8`（对手 6 → 4）挤出上限，削点集变空集。
- 战术层：新增 `pressure_you` / `pressure_opponent` / `pressure_cut_points` 三个事实，
  `ALL_MECH` 17 键；削点只在「压力落后」时算。
- 接管链：在 `vctDefense` 与 `live3Attack` 之间插 `pressureGate`，成**十四级**。
- 开火条件四条：版本闸门 + 有削点 + 压力落后 + **对手没有 danger 点**（安全线，见 ADR-0017 决定 6：
  p18 夹具抓到过「只认手数、不认对手下一步的杀」的反例）。
- 削点为空则不开火 ⇒ 与 v12 逐字一致（最小回归面）。

## 5. 验证证据

- `test/engines/tactics.test.mjs` ⑤e 四例（夹具 = 归档局 `e3e417e6` 第 8 手，见 ADR-0017「验证」）。
- `node test/engines/run.mjs` **139 例全过**（原 135，+4）；金样逐手差分不变（自对弈 1131 手 +
  归档 54 局 4379 手逐手一致）；`npx vitest run` 34 文件 / 337 例全过；`npx tsc --noEmit` 0 错。
- 回归风险扫描（`.work/v13-cut-check.mjs`，逐手用 v13 重算三个 v12 回合）：
  **800 个 Jev 回合**，「有削点且压力落后」**78 手（9.8%）**，**闸门真接管 26 手（3.3%）**，
  被更高层挡住 52 手（`vcfDefense` 40 / `parry4` 7 / `vcfAttack` 5 / `open4` 3 / `vctAttack` 3 /
  `vctDefense` 1 —— 优先级正确，不是漏杀）；
  - 收益：78 手里对手做四手数 **更优 24 / 持平 54 / 更差 0**，平均 −0.69；双四威胁 **45 → 30**；
  - 代价：真接管的 26 手里我们自己的做四手数 **平均 −1.92 个**、13 手让掉攻势（有意的取舍）；
  - 攻击侧零影响：不与 `win` / `block` / `vcf*` / `vct*` 任何一层抢；
  - 成本：`pressureCut` 单次均值 **4.0 ms** / 中位 3 / 最坏 9 ms（n = 78）。
- 逐轮：`115126` 198 回合 / 条件满足 25（12.6%）/ 真接管 7；`121700` 239 / 21（8.8%）/ 6；
  `123631` 363 / 32（8.8%）/ 13。

## 7. 未闭环

1. **代价只有离线量化**：「真接管时让自己做四手数平均 −1.92 个」是手数量，不是胜率；
   只有同口径 A/B 才能说明「用攻势换安全」是否划算。
2. **`live3After` 的缺陷仍在**（ADR-0015 判定「盘面任意 L2 点」口径不对，`live3Deny` 因此常空）——
   本版没改它（改它会同时改变 v10/v11/v12 的行为，A/B 不再是单变量）。
3. **`danger_points_opponent` 这条安全线是启发式**：它来自引擎 criteria，不是「对手下一步必胜」的证明；
   实测 p18 那类局面靠它挡住，但更细的判据（逐点试走验杀）会贵一个量级。
4. **战术层最坏值仍受上游重试影响**：单步墙钟最坏 36 s 级别来自模型往返重试，不是战术层（v12 §7 已记）。

## 8. 下一版候选（按证据强度排序）

1. **压力闸门的代价调优**：把「让掉自己攻势」当约束（只在削点不降低自己做四手数时才开火），
   与现在这版做 A/B 对照 —— 这是本轮唯一带已知代价的机制。
2. **`live3After` / `live3Deny` 的口径修正**（单独一版 + 单独 A/B：会同时影响 v10/v11/v12 三档）。
3. **长局收官**：2 s 档出现过 225 手满盘和棋，长局里的重复与循环（同一局面第 2 次出现）值得单独看。
