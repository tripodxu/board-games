# 2026-10-14 · 官方 API 基准计划：把「真 Jev」量出来，作为一切比分的参照系

> **本文在采样前写死。** 目的是确立基准与判据，事后不得改判据再解释结果。

## 一、为什么要做

2026-08 起积累的所有实验都跑在 **jev-router 网关**上。网关按 `config.json.upstreams`
把请求轮换到多条腿，**free 腿（`jev-1.13-free`）占比在各批次间是 1.0%–99.8%**（跨度 99 个百分点）。
受控跨腿对比显示付费腿与 free 腿只有 50% 的局面选点相同。

**但从未回答过一个更根本的问题**：**jev-router 相对官方 API 到底偏多少？**
没有这个基准，就无法判断跨轮比分被污染的**量级**，只能说「不可比」——这是不可行动的结论。

官方 API（`api.typesafe.ai`，模型 `jev-1.13.0`）是**单上游、无腿路由**的直接来源，
是最接近「真 Jev」的参照系。

## 二、已验证的前置事实（2026-10-14 实测）

| 项 | 结果 |
| --- | --- |
| 端点 | `https://api.typesafe.ai/v1/systemone` |
| **可用模型名** | **`jev-1.13.0`**（别名 `jev-latest` 归一到它） |
| 无效模型名 | `jev-1.13` / `typesafe/jev` / `jev` / `typesafe` → 400 Unknown model |
| 假 key | 401（证明 key 校验正常；本计划所用 key 有效） |
| **地域限制** | **只影响开发机**（451 `Typesafe is not available in your region`）；**box 出口 185.242.234.48 不受限** |
| **速率** | 连打 20 次 **20/20 成功、8 秒**（≈150 次/分），响应头**无 rate-limit 字段** |
| 单次耗时 | ≈0.4 秒（对比网关 1.1–1.3 秒） |

⇒ **官方 API 比网关快约 3 倍且不限速。** 若基准成立，
**今后实验可直接打官方 API，从根上消除腿混合这个污染源。**

## 三、设计：四组端点在同一批真实局面上配对采样

| 组 | 端点 | 模型 | 性质 |
| --- | --- | --- | --- |
| **A 官方** | `api.typesafe.ai/v1/systemone` | `jev-1.13.0` | **基准（真 Jev）**，单上游 |
| B 网关默认 | `172.18.0.4:8080`（无 leg 参数） | 按腿归一 | **日常实验实际跑的面** |
| C 网关 paid | `?leg=lfree-1&strict=1` | `jev-1.13` | 付费腿 |
| D 网关 free | `?leg=zen-o2a&strict=1` | `jev-1.13-free` | free 腿 |

**局面选取**：从历史归档挑**真实对局**的中盘/残盘（**不用合成局面**），覆盖三种混合比例下
自然产生的局面分布：

| 来源批次 | free 腿占比 |
| --- | --- |
| `vplus-r10s`（v14-plus vs rapfi） | 84.1% |
| `v15-vs-r10`（v15 vs rapfi） | 1.0% |
| `vdef-3v-p`（v14.3 vs v14-plus） | 99.8% |

**采样量**：**100 个局面 × 每组 8 次**（A 组 10 次看自身稳定性）= 约 3800 次调用。

- 官方：1000 次 × 0.4s ≈ **7 分钟**
- 网关：受限速 18/分/腿 ⇒ 每腿 800 次 ≈ **45 分钟**（三组可并发）
- **合计约 50 分钟**

## 四、指标

1. **官方自身一致性**：同一局面 10 次的选点一致率（官方是否比网关更确定）
2. **官方 vs 网关默认**（核心）：选点一致率 + 概率向量 TV 距离 ⇒ **网关是否忠实**
3. 官方 vs paid、官方 vs free
4. 各组内部 split-half（概率分布稳定性）
5. 耗时对比
6. **置换检验**给出 p 值（零假设用「混池随机对半」的经验基线，不用「Σp²」——那个假设已被实测推翻 10–14 倍）

## 五、判读规则（跑前写死）

| 观测 | 结论 |
| --- | --- |
| 网关默认 vs 官方：选点一致 **>85%** 且 TV **<0.1** | **腿路由不改变行为** ⇒ 跨轮比分的污染担忧作废，历史上所有跨轮比分可重新采信；今后可直接打官方 |
| 网关默认 vs 官方：一致 **60–85%** 或 TV **0.1–0.3** | 部分偏离 ⇒ 结合 free 腿占比跨度 1%–99.8%，给出**跨轮比分污染上界**；今后基准一律用官方，或报告与官方的偏差 |
| 网关默认 vs 官方：一致 **<60%** 或 TV **>0.3** | 显著偏离 ⇒ 跨轮比分**确认不可比**，所有历史跨轮结论需按此折价 |
| 官方自身一致率 **<80%** | 「真 Jev」本身也不确定 ⇒ 一切单次调用对比都要按此噪声地板折价，与腿无关 |

## 六、顺带确立的口径

跑完后写入 `docs/status.md` 与 MEMORY：

1. **「真 Jev」= 官方 API `jev-1.13.0`**，不是 jev-router 的任何一条腿。
2. **今后主实验默认打官方 API**（更快 3 倍、无限速、无腿混合）；用 jev-router 时必须报告与官方的偏差。
3. 归档里 `blackChannel/whiChannel = official` 的 7 个批次（`v15val`/`v16val`/`v16pair`/`vorder1`/`vplus1`/`rapfihi1`/`p6val`）本就是干净的，可作交叉校验。
4. **模型名只能用 `jev-1.13.0` 或 `jev-latest`**（`typesafe/jev` 是记录字段、不是可用名）。

## 七、前置与风险

1. **key 落位**：装到 box 的 `/root/.jev-official-key`（与既有 `/root/.jev-router-key` 同级），
   只从文件注入环境变量，**不入仓库、不进日志、不进命令行**。规则 7。
2. **额度**：官方 API 实测无限速，但可能有月度额度；3800 次调用前建议确认。
3. **key 安全**：本计划所用 key 已在对话中明文出现，**建议测完轮换**。

## 八、与在跑的实验的关系

已有一个 **100 局面 × paid/free 跨腿检验**（`.work/leg-equiv-large.mjs`）在跑，它测的是
**网关内部两条腿**的差异。本文测的是**官方 vs 网关**——后者才是跨轮比分的真正混淆源。
两者互补，都需要。

## 九、结果（2026-10-14 实测）

数据集已落盘 `docs/experiments/`（README 有完整说明与用法）。

**官方 API 自身的确定性（真 Jev 的噪声地板）**：

| 数据集 | 众数占比（重复问选同一着法的比例） | R=众数/Σp² |
| --- | --- | --- |
| 大样本 500×6 | **93.2%** | 15.3 |
| 小样本 96×10 | **90.9%** | 14.1 |

两批互印（差 2.3pt）。**⇒ Jev 是随机的，不是确定函数**：约 7–9% 的局面重复问会给出不同着法。
R≫1 表明它**不按自报概率抽样**（比概率声明确定得多）。

**两个此前的说法被本次实测修正**：
1. 「instructions 由注册档位+代码确定」**不准确** —— 实测同一 SHA 横跨多个档位，差异由**局面的 tactics 事实**决定；
   故数据集自带 instructions 去重字典（全库仅 4 份），复现**不依赖代码版本**（已 500/500 校验）。
2. 「网关侧 split-half r=0.939 ⇒ 有确定值」方向对但数字被高估 —— 官方自身众数占比 93.2% 是**更该信的噪声地板**；
   用它取代网关侧数字作为渠道判别的基准。

**判等价的正确指标**（写进 README）：新渠道在**同一批 500 局面**上跑 ≥6 次，比
「众数一致率」（>85% 且 TV<0.1 判等价）与**概率向量 TV 距离**；不要看「与归档实走一致率」——
那是另一个问题（重建输入 ≠ 生产实送，实测实走∈采样 100% 但实走=众数仅 31.3%）。

**踩到并已修的坑**：采样器一度按 `channel==='jevrouter'` 过滤局面，漏掉 2026-10-08 前走
`official` 渠道的批次（v14.1/v14.2 采到 0 个）；改为按**战术档**筛后 500 局面配额填满。
棋盘局面与渠道无关。
