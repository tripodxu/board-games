# 计划与执行记录：战术 v12 `v12-vct-def`（连续威胁防守）与 Rapfi 0.5s 对照实验

- 状态：**进行中**（2026-10-02：机制/实现/单测已落盘，文档与实验进行中）
- 触发：用户在 v11 交付后给出新目标（m08704）：「根据所有跑的有价值的实验整合出下一版本的
  战术优化，并过一下已有的棋谱信息，不一定要全量，看看优化是否有回归降低能力的风险，
  之后再与 rapfi 跑，当胜率多版本稳步上升之后，提高 rapfi 的思考时间，不要忘记写实验报告
  和文档的更新优化工作，如此迭代」——本计划只覆盖其中「下一个版本」这一轮。

## 1. 目标

1. **整合已有实验**：把 v9 / v10 / v11 三轮对照实验、两轮 v11 vs `rapfi@500ms`、
   一次 `v10` vs `v11` 同门直连的棋谱与逐手数据放在一起，回答「**现在还剩哪一类局面会输**」。
2. **过已有棋谱看回归风险**：在归档棋谱上逐手重算新机制，量化「会改掉多少手、改对多少手」，
   再决定这一版做不做、做多大。
3. **优化**：给出第十二版战术（登记表第 13 行 `v12-vct-def`），机制变化要能用数字说清
   「修掉的是哪一类漏防」。
4. **实验**：`v12-vct-def` vs `rapfi@500ms`，与 v9 / v10 / v11 三臂**同对手、同开局、同局数**
   口径对比，看胜率是否**稳步上升**（这是 m08704 里「稳步上升后再提高 rapfi 思考时间」的前提）。

### 2.1 进攻侧已经没有可见漏杀（三轮一致）

输在「算不出强制胜」的局面，不是漏杀。

### 2.2 漏洞在防守侧：只有纯冲四链的拆法

`.work/v12-defence-probe.mjs` 逐 proxy 回合算「我方 VCF/VCT、对手 VCF/VCT、实走后对手是否仍有杀」：

- 计时轮 175 个 v11 回合：我方有杀 **72 手（41%）**；**我方无杀而对手有链 20 手（11%）**；
  实走之后对手**仍有杀 8 手（40%）**，且**全部落在三局负局**（`#5 6db0253d` ply17/19/21/23、
  `#6 68f62f4b` ply32/34、`#8 f463acff` ply24/26）；
- 8 手里 **4 手的实走正是对手的链首点** —— 占掉链首**并没有**拆掉整条链；
- 直接走链首能拆的比例 **12/20（60%）**，这 12 手全部由**已有的** `vcfDefense`（10）与
  `block`（2）拆掉 ⇒ 现有防守层「要么已经拆掉，要么根本没看见」：它只验**纯冲四**链。

### 2.4 候选集怎么选（四种策略对照）

`.work/v12-defuse-strategies.mjs`，在「我方无杀而对手有链」的回合上比命中率：

| 轮次（机会数） | A 只试链首 | B 链首 + 链上各点 | C + 链点车氏 ≤2 邻域 | D 全部邻近空点按到链距离 |
| --- | --- | --- | --- | --- |
| 计时轮（20） | 12 | 12 | **13** | **13** |

## 3. 设计：拆掉对手的混合链

1. 引擎新增 `vctDefense(st, defenderId, maxPlies?, opts?)`：先算对手的链（有 VCF(7) 用它，
   否则算含活三逼迫的 VCT(9)），再按「链上各点 → 链点车氏 ≤2 邻域 → 全部邻近空点（按到链
   距离升序）」枚举候选，上限 `VCT_DEF_MAX = 12`。
2. 判据：落子后对手**既无 VCF(7) 也无 VCT(9)**（外加「没有一手成五」兜底）——比 `vcfDefense`
   的「只验纯冲四链」严一档。
3. 并列拆法按 1-ply 取势排序（模型候选优先，其次对手造四点 ×2 + 活三点更少者优先），
   保留 `VCT_DEF_KEEP = 3` 个。
4. 战术层新增 `vct_win_opponent` / `vct_chain_opponent`，`ALL_MECH` / `MECHS` → **16 键**，
   接管链在 `vcfDefense` 与 `live3Attack` 之间插 `vctDefense` 成**十三级**。
5. 闸门：我方无 VCF/VCT 必胜链、`vcfDefense` 没找到拆点、`block`/`win` 都空时才开火
   （实测「我方无杀而对手有链」占我方回合 ≤11%，回归面因此最小）。

设计依据与取舍详见 [ADR-0016](../adr/0016-vct-defense.md)。

## 5. 验证证据

- `test/engines/tactics.test.mjs` ⑤d 五例（夹具 = 归档局 `f463acff` 第 24 手，见 ADR-0016「验证」）。
- `node test/engines/run.mjs` **135 例全过**（原 130，+5）；金样逐手差分不变（自对弈 1131 手 +
  归档 54 局 4379 手逐手一致）；`npx vitest run` 34 文件 / 337 例全过；`npx tsc --noEmit` 0 错。
- 回归风险扫描（`.work/v12-regression.mjs`，逐手用 v12 重算已归档的三轮 proxy 棋谱）：
  **36 局 / 983 个 v11 回合**，防守机会 **118 手**（`vcfDefense` 老层已认领 51 手），
  `vctDefense` **开火 13 手**，其中 **真救 3 手**、**本就拆掉 10 手**、**拆不掉 0 手**，
  「我方有必胜链」**163 手不变**（闸门不抢必胜层）。逐局明细见 `.work/v12-regression.json`：
  - 真救：计时轮 `f463acff` ply24 实走 `I11/parry` → `K9`；直连轮 `d879b7bc` ply50 实走 `J5/parry`
    → `H5`；直连轮 `986185dc` ply18 实走 `G10/live3Defense` → `F9`。
  - 「本就拆掉」这一档正是**回归风险为零**的实证：这 10 手实走也已经拆掉了对手的链，
    v12 只是同样能拆 —— 改动无害，不是改坏。
  - 同一批回合的战术层耗时：中位 **155 ms** / 均值 247 ms / p90 605 ms / 最坏 **4474 ms**；
    开火的 13 手：中位 1080 ms / 均值 1534 ms / 最坏 4474 ms。

1. **压力闸门（下一版入口）**：对手「造四点」数压过我们时不要抢 `live3Attack`，改走削他造四点数的点。
   证据已在 §2.3，但它改变进攻选择，必须单独一版 + 单独 A/B。

   ply22，正是开火局面），与 v11 自身最坏同量级、未放大一个数量级；实战 `tac_ms` 最坏值看
   §6 回填。
